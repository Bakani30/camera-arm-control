# การพัฒนาระบบควบคุมแขนกลผ่านกล้อง
**Vision-Based Robotic Arm Control System**

รุ่น 3.4 · 2026-11-04 · ฐานเนื้อหาสไลด์เสนออาจารย์ 9 หน้า + ปก คุยภายในทีมก่อนเสนอจริง (B นำทำสไลด์และจัดโครงหน้า ทั้งทีมคิดร่วม) · เนื้อหาตัดสินโดยโรล C (D01, D27, D31, D33–D35, D40–D42) ผู้ทำสไลด์จัดรูปแบบได้ ถ้าจะเปลี่ยนเนื้อหาให้คุยกับ C ก่อน

**ไม่ขึ้นสไลด์:** งบและราคา, ผลวัดกล้องรอบแรก, การตัด AI, โค้ดทดลอง TensorFlow (D27, D31, D41) · **ห้ามอ้าง:** รองรับทุกแขน, ดีกว่าจอย, ภาพจำลองเป็นผลการทดลอง (D32)

**เปลี่ยนจากรุ่น 3.3:** แยกที่มา วัตถุประสงค์ และขอบเขตเป็นคนละหน้า; เขียนที่มา ความสำคัญ วัตถุประสงค์ และชื่องานในตารางเวลาใหม่ (ช่วงเดือนเดิม); ย้ายการประเมินผลไปรวมกับผลที่คาดหวัง; ตัดวิดีโอ mock arm ออกจากสื่อ; ชื่ออังกฤษเปลี่ยนเป็น "Vision-Based Robotic Arm Control System" ตามที่ B เสนอ (D31 ยังเป็นชื่อเดิม รอ C ยืนยัน); รวมที่มากับความสำคัญเป็นรายการเดียว

## ปก

- อังกฤษ: Vision-Based Robotic Arm Control System

## สไลด์ 1 · ที่มาและความสำคัญ

การควบคุมแขนกลในปัจจุบันต้องใช้อุปกรณ์เฉพาะทาง เช่น teach pendant ของแขนอุตสาหกรรม แขนต้นแบบแบบ leader–follower (เช่น SO-101) หรือคอนโทรลเลอร์ VR (เช่น Meta Quest) ซึ่งผู้ใช้ต้องถือหรือสวม และต้องเรียนรู้วิธีสั่งงานของแต่ละแบบ ในหลักการ เว็บแคมทั่วไปตัวเดียวอ่านตำแหน่งมือ การหมุนข้อมือ และท่าทางนิ้วได้ แต่มือกับแขนกลมีสเกลต่างกัน หากแปลงการเคลื่อนที่โดยตรงจะคุมไม่ละเอียดหรือเอื้อมไม่ถึง โครงงานนี้จึงพัฒนาระบบสั่งแขนกลด้วยมือผ่านเว็บแคม พร้อมวิธีแปลงสเกลที่คุมได้ละเอียดใกล้เป้าหมายและเคลื่อนที่ได้ไกลเมื่อต้องการ ช่วยลดอุปกรณ์ฝั่งผู้ใช้ และให้ผู้ใช้สั่งงานแบบเดียวกันกับแขนต่างขนาดได้ (เฉพาะแขนที่ผ่านการทดสอบ)

## สไลด์ 2 · วัตถุประสงค์
1. เพื่อพัฒนาระบบติดตามตำแหน่งมือ การหมุนข้อมือ และท่าทางนิ้วจากกล้อง RGB ตัวเดียว สำหรับใช้เป็นคำสั่งควบคุมแขนกล โดยควบคุมเฉพาะองศาอิสระที่แขนแต่ละรุ่นรองรับ
2. เพื่อพัฒนาวิธีแปลงสเกลการเคลื่อนที่จากมือไปยังแขนกลที่มีพื้นที่ทำงานต่างกัน ผ่านรูปแบบข้อมูลกลางที่ใช้ร่วมกัน
3. เพื่อประเมินความแม่นยำและความง่ายในการสั่งงานของวิธีแปลงสเกล โดยเปรียบเทียบการแมปแบบสัมพัทธ์ (relative) กับแบบไฮบริดบับเบิล (hybrid bubble) ทั้งในสภาพแวดล้อมจำลองและบนแขนกลจริง

## สไลด์ 3 · ขอบเขตงาน
- กล้อง RGB หนึ่งตัว ผู้ใช้หนึ่งคน มือเดียว แสงและตำแหน่งกล้องคงที่ ปรับเทียบก่อนใช้งานได้
- แขนสองขนาด: แขนจริงขนาดเล็ก (ของจริงและในซิม) และแขนอุตสาหกรรมในซิม เช่น UR5e ยืนยันรุ่นหลังตรวจ MuJoCo บน Windows
- ระยะที่สอง ถ้าทันตามจุดตัดสินกลาง ก.พ.: มือหลายนิ้วในซิมที่คุมทีละนิ้ว

## สไลด์ 4 · Block diagram
ผู้ทำสไลด์วาดใหม่ได้ แต่ลำดับกล่องและชื่อต้องคงตามนี้

```mermaid
flowchart LR
  CAM[เว็บแคม RGB] --> MP[MediaPipe<br/>จุดมือ 21 จุด]
  KEY[ปุ่มบนคอม<br/>เริ่ม พัก สเกล] --> MAP
  MP --> MAP[ระยะมือเทียบฝ่ามือ<br/>สเกลตาม workspace<br/>hybrid bubble + กรองสัญญาณ]
  MAP --> T1[[ข้อมูลกลาง 1<br/>เป้าหมายปลายแขน หน่วยเมตร]]
  T1 --> IK[โปรไฟล์แขน + IK<br/>+ ขีดจำกัด]
  IK --> T2[[ข้อมูลกลาง 2<br/>คำสั่งข้อต่อ]]
  T2 --> SIM[ซิม MuJoCo<br/>แขนเล็ก + แขนอุตสาหกรรม]
  T2 --> DRV[ตัวแปลแขนจริง<br/>+ ด่านความปลอดภัย]
  DRV --> ARM[แขนจริงทรง 4.1]
  ARM -. มุมที่วัดได้ .-> LOG[บันทึกผล]
  ARU[กล้องวัด + ArUco] -.-> LOG
```

- **ข้อมูลกลาง** ทำให้ส่วนมือไม่ต้องรู้จักแขน เพิ่มแขนรุ่นใหม่ = เพิ่มโปรไฟล์ + ตัวแปล
- **หยุดสองชั้น** (D30): คำสั่งพักหรือมือหาย = แขนค้างท่า; ปุ่มหยุดฉุกเฉิน = ตัดไฟมอเตอร์
- **แบ่งงานตามเลน** (D23): A มือ → เป้าหมาย · B เป้าหมาย → ซิม · C ข้อมูลกลาง + แขนจริง

## สไลด์ 5 · วิธีการและโมเดล 3D
พูดวิธีการไปพร้อมโมเดลแขน

**คุมด้วยมือ** (ชุดเริ่มต้น จะล็อกหลัง gesture study, D40, D42)
| ผู้ใช้ทำ | แขนทำ |
|---|---|
| กด C | เริ่มตาม ก่อนกดแขนรอนิ่ง |
| ขยับมือซ้าย-ขวา ขึ้น-ลง | ปลายแขนตาม |
| ดันมือเข้า-ออกกล้อง | ระยะเอื้อม |
| ก้มและบิดข้อมือ | มุมก้าม เฉพาะแกนที่แขนทำได้ |
| กำมือ / แบมือ | ก้ามปิด / เปิด |
| กด Space แล้ว C | พักแล้วตามต่อโดยไม่กระโดด ใช้จัดมือกลับกลางได้ |

**แปลงสเกล**
- ระยะมือคิดเทียบขนาดฝ่ามือ → สเกลตาม workspace ของแขน → เป้าหมายปลายแขนหน่วยเมตร
- สเกล 1 = ขยับมือเต็มระยะแล้วแขนไปได้เต็ม workspace ของรุ่นนั้น เลือก 0.5 (ละเอียด), 1 หรือ 1.25 ได้
- Hybrid bubble: ในฟองคุมตำแหน่งแบบละเอียด นอกฟองแขนเลื่อนต่อตามทิศ มีเพดานความเร็ว และหยุดทันทีเมื่อมือหาย
- การหมุนข้อมือใช้แนวคิดเดียวกัน: บิดนิดเดียวแขนหมุนตามมุม บิดเกินช่วงแขนหมุนต่อเนื่องจนกว่ามือกลับกลาง

**งานทดสอบ:** เคลื่อนตามเป้าหมาย, หยิบบล็อก 4–5 ซม. วางในถาด, กดปุ่ม ~3 ซม.

**สื่อ** (คำบรรยาย: "ภาพจำลองจากโมเดล CAD เพื่ออธิบายวิธีการ ไม่ใช่ผลการควบคุมด้วยกล้อง และไม่ใช่การจำลองฟิสิกส์")
- [โมเดลแขน 3D](https://claude.ai/artifact/RYQY3PPRSpPc8iUWpzp848): หมุนดูแบบ CAD ปัจจุบัน

## สไลด์ 6 · แขนจริงและอุปกรณ์
**แขนจริง**
- CAD ของทีมเอง ทรง FABRI Brazo Robótico 4.1 (วาดเองจากภาพสาธารณะ ไม่ใช้ไฟล์ผู้ขาย) บนจลนศาสตร์ SO-101 แบบเปิด (Apache-2.0) 5 แกน + ก้ามหนีบ พิมพ์ 3D ประกอบเอง ฐานกลมหมุนรอบวง ±180° เก็บชิ้น SO-101 เป็นแผนสำรอง
- ระยะเอื้อมคำนวณ ≈ 42 ซม. จากแกนไหล่ (ยังไม่วัดจริง)
- Bus servo อ่านมุมกลับได้ทั้ง 6 ข้อ: Feetech STS3215 12V ×4 ที่ฐาน ไหล่ ศอก ข้อมือก้ม-เงย + STS3032 6V ×2 ที่ข้อมือหมุนและก้าม
- ภาพ: `cad/shell_v1/renders/ready_front34.png`, `ready_back34.png`, `zero_side.png` คำบรรยาย "แบบ CAD ยังไม่ได้พิมพ์หรือประกอบจริง"

**การต่อฮาร์ดแวร์**
```mermaid
flowchart LR
  CAM[เว็บแคม] -- USB --> PC[คอมพิวเตอร์ Windows]
  PC -- USB --> BUS[Bus Servo Adapter]
  BUS -- TTL bus --> STS[STS3215 ×4<br/>ฐาน ไหล่ ศอก ข้อมือก้ม-เงย]
  BUS -- สายข้อมูลร่วม --> S32[STS3032 ×2<br/>ข้อมือหมุน ก้าม]
  AC[ไฟบ้าน] --> ES[ปุ่มหยุดฉุกเฉิน] --> PSU[PSU 12V 10A]
  PSU --> BUS
  PSU --> BUCK[buck ~6V] --> S32
```
วิธีแยกไฟ 6V ของ STS3032 ยังไม่ล็อก ผังนี้เป็นแนวทางปัจจุบัน (D33, D35)

หน้านี้เนื้อหาแน่น ถ้าลงหน้าเดียวไม่พอ ผู้ทำสไลด์แยกแขนจริงกับผังต่อไฟเป็นอีกหน้าได้

## สไลด์ 8 · ผลลัพธ์ที่คาดหวังและการประเมินผล
**ผลลัพธ์ที่คาดหวัง:** ระบบต้นแบบที่ใช้มือเดิมคุมแขนกลต่างขนาดได้ผ่านกล้อง พร้อมผลทดลองที่แสดงว่าวิธีแปลงสเกลช่วยเรื่องความแม่นยำและความง่ายได้แค่ไหน และข้อจำกัดที่พบ

**วิธีประเมิน:** วัดความแม่นยำแยก 4 ชั้น ได้แก่ ความซ้ำได้ของแขนเอง, ความนิ่งของเป้าหมายจากกล้อง, ความคลาดเคลื่อนปลายแขนทั้งระบบ และอัตราสำเร็จของงาน พร้อมเวลาทำงาน ความต่อเนื่อง ความหน่วง และ Fitts' law throughput เทียบ mapping สองแบบภายใต้เงื่อนไขเดียวกัน รายงานผลในซิมและบนแขนจริงแยกกัน เกณฑ์ผ่านเชิงตัวเลขตั้งหลังรอบ pilot (มี.ค.) จากข้อมูลจริง

## สไลด์ 9 · ความเสี่ยงและความเห็นที่ขอ
| ความเสี่ยง | รับมือ |
|---|---|
| กล้องตัวเดียวอ่านระยะลึกคลาดเมื่อท่ามือเปลี่ยน | ชดเชยจากเรขาคณิตมือ, ค้างเป้าหมายช่วงเปลี่ยนท่า, โหมด Z แยกเป็นทางสำรอง |
| การอ่านมุมบิดข้อมือ | วัดซ้ำบนเครื่องทดลอง, หาวิธีอ่านใหม่ หรือคุมก้มกับบิดคนละจังหวะ |
| ความหน่วงทั้งระบบทำให้โซนนอกฟองเลยเป้า | วัดก่อนจูนฟอง และมีเพดานความเร็ว |
| แขนจริงมาช้า | แฝดซิมและ fake servo ทำงานแทนระหว่างรอ |

**ความเห็นที่ขอจากอาจารย์**
1. ขอบเขตแขนสองขนาดและงานทดสอบเหมาะสมไหม
2. วิธีประเมิน 4 ชั้นและการเทียบ mapping สองแบบเพียงพอไหม

## เตรียมตอบ (ไม่ขึ้นสไลด์)
- **ใช้ AI ไหม:** MediaPipe เป็นโมเดลอ่านมือสำเร็จรูป ส่วนการแปลงการเคลื่อนไหวเป็นวิธีคำนวณ เราไม่ได้ฝึกโมเดลเอง
- **ทำอะไรไปแล้ว:** ต้นแบบอ่านมือบนกล้องจริง, รูปแบบข้อมูลกลางพร้อมเทสต์, CAD แขนและการทดสอบมูฟเชิงเรขาคณิต ทั้งหมดยังไม่มีการขยับแขนจริงหรือซิมฟิสิกส์
- **ตัวอย่างอุปกรณ์ในสไลด์ 1 มาจากไหน:**
  - teach pendant: วิธีสอนงานแบบดั้งเดิมของแขนอุตสาหกรรม ติดมากับตัวแขน ([RoboDK](https://robodk.com/blog/robot-programming-methods-pros-and-cons/)) ตัวเลข "หุ่นยนต์กว่า 90% สอนงานด้วยวิธีนี้" มีแค่ในบล็อกผู้ขาย ยังไม่พบต้นทาง อย่าอ้างตัวเลขนี้
  - leader–follower: GELLO ([arXiv 2309.13037](https://arxiv.org/abs/2309.13037)), ชุด SO-101 ของ LeRobot ที่มีแขน leader กับ follower ([เอกสาร Hugging Face](https://huggingface.co/docs/lerobot/so101))
  - คอนโทรลเลอร์ VR: OPEN TEACH ใช้ Meta Quest 3 (CoRL 2024, [arXiv 2403.07870](https://arxiv.org/abs/2403.07870))
- **ผลวัดกล้องรอบแรก:** ดู `docs/research/hardware-notes/2026-11-02-hand-axis-bench-results.md` มาจากคนเดียว เครื่องเดียว ยังไม่ใช่ค่าของทีม
