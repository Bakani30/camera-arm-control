# แผนลดงบมอเตอร์และใช้เซอร์โวผสม
วันที่ 2026-10-02 · ต่อจาก R001 · สถานะ: ข้อเสนอเพื่อเทียบ ยังไม่เลือกหรือทดลอง

## ข้อกำหนดที่ผู้ใช้ยืนยัน
เป้าหมาย **มอเตอร์รวมประมาณ 3,000 บาท ±** อุปกรณ์อื่นคิดแยก ผู้ใช้ยังไม่ได้ระบุขอบเขต ± เป็นตัวเลข กรอบฮาร์ดแวร์รวมเดิม 10,000 บาทยังไม่ถูกเปลี่ยน ใช้แบบแขนของผู้อื่นเป็นฐานแล้วปรับแต่งได้ งานจริงลูกบล็อก มือเดียว แขนจริงหนึ่งตัว ช่วงนี้วางแผนเท่านั้น

ผู้ใช้ยืนยันเพิ่มเติม: **เน้นการหมุน การตอบสนองเร็ว และความแม่นยำของการควบคุมผ่านกล้อง ไม่ต้องยกวัตถุหนัก** ดังนั้นแรงบิดเป็นเงื่อนไขให้รับโครง/ก้าม/บล็อกเบาได้ ไม่ใช่เกณฑ์แข่งขัน payload สูง ความเร็ว มุมหมุนที่ใช้จริง backlash และการวัดผลสำคัญกว่าเลือกมอเตอร์จากค่าแรงบิดโฆษณาเพียงอย่างเดียว ยังไม่กำหนดว่าต้องหมุนต่อเนื่อง 360° หรือเกณฑ์ผ่านเชิงตัวเลข

## ชุดมอเตอร์สำหรับเทียบ
สามชุดแรกสมมติ **6 แกนแขน + ก้ามหนึ่งตัว = 7 มอเตอร์** หนึ่งมอเตอร์ต่อแกน ไม่ใช่การยืนยัน topology ของรุ่นใด แบบที่ใช้มอเตอร์คู่หรือ linkage อื่นต้องนับใหม่

| ทางเลือก | จำนวนมอเตอร์ | คำนวณบาท | ข้อแลกเปลี่ยน |
|---|---|---:|---|
| PWM ล้วน เป็นฐานเทียบต้นทุน | 2 TD8120MG + 4 MG996R + 1 MG90S | 2×480 + 4×175 + 75 = **1,735** | ระบบควบคุมกลุ่มเดียว; ไม่มีมุมวัดกลับผ่าน interface PWM มาตรฐาน |
| ผสม เน้น PWM กลุ่มแรงบิดสูง | 1 SC15 + 3 TD8120MG + 2 MG996R + 1 MG90S | 1,185 + 3×480 + 2×175 + 75 = **3,050** | อ่านมุมวัดเพียงหนึ่งข้อ; แรงบิด/ตำแหน่งที่จะใช้ยังต้องคำนวณ |
| ผสม อ่านมุมสองข้อ | 2 SC15 + 4 MG996R + 1 MG90S | 2×1,185 + 4×175 + 75 = **3,145** | อ่านมุมสองข้อ; ไม่รับรองว่า SC15 แรงกว่า PWM หรือว่า MG996R ทุกข้อพอ |
| ตัวเทียบ 5 แกน + ก้าม = 6 มอเตอร์ | 2 SC15 + 3 MG996R + 1 MG90S | 2×1,185 + 3×175 + 75 = **2,970** | ใกล้รูปแบบ SO-101/UMIRobot ด้านจำนวนแกนเท่านั้น; ไม่ใช่มอเตอร์เสียบแทนได้ทันที |

ถ้าก้ามต้องเปลี่ยน MG90S เป็น MG996R เพิ่ม **100 บาท** ต่อชุด แต่ต้องแก้ขนาด/น้ำหนัก/กลไก ไม่ถือว่าก้ามใหม่จะจับบล็อกได้โดยราคาอย่างเดียว ไม่เสนอ SG90 เพื่อประหยัดเพียง 11 บาทก่อนรู้แรงจับที่ต้องการ

**ข้อเสนอตามความสำคัญล่าสุด:** ศึกษาชุดผสมอ่านมุมสองข้อ **3,145 บาท** ก่อน โดยเทียบกับ PWM ล้วนและชุดผสม 3,050 บาท การมี readback ช่วยตรวจคำสั่งกับการเคลื่อนที่เฉพาะข้อที่ติดตั้ง แต่ไม่ใช่หลักฐานว่าตอบสนองเร็วหรือแม่นกว่า ต้องตรวจความเร็วภายใต้โหลดและ backlash จริงก่อนเลือก ยังไม่ล็อกซื้อ SC15 หรือจัดลงไหล่/ข้อศอกตอนนี้

## เกณฑ์ตัดสินตามงานกล้อง — เสนอวิธีวัด ยังไม่ตั้งเกณฑ์ผ่าน
| สิ่งที่ต้องได้ | วิธีตรวจในช่วงทดลอง |
|---|---|
| หมุนครอบคลุมท่าที่ต้องใช้ | ระบุช่วงมุมแต่ละแกน/ท่าข้อมือและข้อจำกัดปลายแขนก่อนเลือก; จำนวนแกนหรือชื่อ 180/270/360° ไม่ยืนยัน workspace ที่ใช้ได้ |
| ตอบสนองเร็ว | วัดเวลาตั้งแต่ภาพเข้าระบบ → เป้าหมาย/คำสั่ง → แขนเริ่มเคลื่อนและถึงเป้าหมาย; รายงานค่ากลางและ p95 แยกจาก FPS กล้อง ต้องมีวิธีจับเวลาการเคลื่อนจริง |
| เคลื่อนที่แม่น | วัดตำแหน่ง/ทิศทางปลายแขนเทียบเป้าหมาย และ repeatability เมื่อเข้าเป้าซ้ำจากต่างทิศ; readback มอเตอร์อย่างเดียวไม่ใช่ ground truth ปลายแขน |
| ลื่นและหยุดตามคำสั่ง | ทดสอบเป้าคงที่/เคลื่อน/กลับทิศ/หายมือ ตรวจสั่น overshoot เวลาเข้าที่และ tracking-loss policy; smoothing มากขึ้นอาจเพิ่มความหน่วง |

baseline เป็นคำสั่งจุด/เส้นทางที่รู้ค่า เพื่อแยกข้อจำกัดมอเตอร์ออกจากความคลาดเคลื่อน tracking แล้วจึงเทียบการควบคุมผ่านกล้องและพิจารณา ML จาก failure ที่พบ เกณฑ์ตัวเลขจะตั้งจาก pilot ไม่สร้างค่าผ่านขึ้นเองตอนนี้

## หลักเลือกข้อต่อและข้อจำกัด
- แยกการเลือก **แรงบิด** กับ **feedback** ไหล่/ข้อศอกมักต้องรับโมเมนต์จากลิงก์ ก้าม และวัตถุ แต่จำนวน/ตำแหน่งมอเตอร์ต้องคำนวณจากแบบจริง ฐานหมุนไม่ได้ต้องใช้มอเตอร์แรงสุดโดยอัตโนมัติ
- ใช้ความยาวลิงก์ มวลแต่ละส่วน และน้ำหนักบล็อกคำนวณโมเมนต์ในท่าที่รับโหลดมาก รวมข้อกำหนดการเคลื่อนที่/เวลาถือ/ความร้อน ค่า stall torque ในโฆษณาไม่ใช่แรงบิดต่อเนื่องที่รับรอง
- เซอร์โว PWM มีการควบคุมตำแหน่งภายใน แต่โปรแกรมเครื่องเราไม่ได้รับมุมวัดจริงผ่านสายควบคุมปกติ แม้บอร์ดตอบค่า position ก็อาจเป็นเพียงพัลส์ที่ส่ง เช่น [Pololu Get Position](https://www.pololu.com/docs/0J40/5.e) ห้ามบันทึก commanded angle เป็น measured angle
- [SC15 ผู้ผลิต](https://www.waveshare.com/wiki/SC15_Servo) ระบุ feedback position/load/speed/input voltage มุมมอเตอร์หนึ่งหรือสองข้อยังไม่พอให้รู้ pose จริงทุกข้อหรือความคลาดเคลื่อนปลายแขน ต้องวัดปลายแขนและการหยิบ/วางแยก
- ร้านไทยระบุ SC15 180° แต่ผู้ผลิตปัจจุบัน 210°; MG996R ร้านไทยกับ [TowerPro](https://towerpro.com.tw/product/mg996r/) ระบุช่วงมุม/แรงดัน/แรงบิดต่างกัน ใช้ราคา SKU ร้านเพื่อวางงบ ไม่ยกสเปกผู้ผลิตมารับรองล็อตที่ยังไม่ตรวจ

## ผลต่อแบบแขนและซอฟต์แวร์
| ฐานที่ค้นไว้ | สิ่งที่ต้องเทียบภายใต้งบมอเตอร์ใหม่ |
|---|---|
| UMIRobot / FABRI | ต้นแบบใช้ hobby PWM อยู่แล้ว เหมาะตรวจงานเปลี่ยนขนาดเซอร์โว/ก้ามและเพิ่ม bus บางข้อ แต่ยังต้องตรวจจำนวนแกนที่โจทย์ต้องใช้ เงื่อนไขไฟล์ และ feedback ของแบบดัดแปลง |
| SO-101 | เหมาะเป็นฐานเทียบ software/model; เปลี่ยนจาก STS3215 เป็น SC15/PWM ต้องแก้ที่ยึด ฮอร์น ช่วงมุม adapter และโมเดล ไม่สรุปว่า LeRobot เดิมใช้ต่อได้ทันที |
| AM-ARM200 / ElRobot | มี CAD ให้ศึกษาโครงหลายแกน แต่ลดงบชุดขับเดิมเป็นงานแก้แบบมากขึ้น ต้องประเมินมวล/แรงบิดใหม่ ไม่รับสมรรถนะหรือผลซิมต้นฉบับมาใช้ |

PWM และ TTL bus ใช้ร่วมกันได้ในเชิงสถาปัตยกรรม โดยมีตัวเชื่อมควบคุมแยกแล้วรวม joint mapping/units/timestamps/logging เดียวกัน ยังไม่ IMPLEMENTED การเลือก controller/รางไฟต้องตรงกับรุ่นจริง ไม่ขับ bus ผ่าน PCA9685 และไม่จ่ายแรงดัน bus สูงให้ PWM โดยไม่ตรวจสเปก ดูวงจร/ราคาอุปกรณ์ใน source note

งบแยกที่ต้องรวมภายหลัง: MCU หรือบอร์ด PWM, bus adapter ถ้าใช้, PSU/วงจรไฟ/วิธีหยุด, ฮอร์น/ลูกปืน/สาย/น็อต, ค่าพิมพ์/ไฟล์/กล้อง/อะไหล่/ส่ง/ภาษี การลดค่ามอเตอร์อาจเพิ่มเวลา CAD และ integration; ยังไม่มี BOM ทั้งแขนที่รับรองครบใน 10,000 บาท

## ลำดับงานระยะยาว — ยังไม่เริ่มทำ
1. ระบุบล็อกจริง น้ำหนัก ระยะเปิดก้าม ระยะเอื้อม และท่าปลายแขนที่ต้องใช้ โดยคงเป้าหมายข้อมือตาม D04; ยังไม่ลดจำนวนแกนตามราคาอัตโนมัติ
2. เทียบแบบ hobby-servo เดิมกับแบบ bus ที่ตั้งใจแก้ เลือก geometry เบา/สั้นเท่าที่งานยอมรับได้ แล้วคำนวณโหลดก่อนลง SKU และตำแหน่งมอเตอร์
3. เทียบ BOM ผสมสองชุดกับ PWM ล้วน รวมต้นทุนอุปกรณ์ที่แยกไว้และงานแก้แบบ; จากนั้นจึงเสนอเลือกรุ่น/แบบจริง
4. เมื่อเข้าสู่ช่วงทดลอง: ตรวจมอเตอร์และ calibration ทีละข้อ ซิม contact บน ASUS และ baseline ฮาร์ดแวร์กับผู้ควบคุมหน้างาน ก่อนเลือกการเรียนรู้จาก failure ที่วัดได้

ตรวจราคา/ข้อเท็จจริงจากแหล่งหลักและ arithmetic; **การประกอบ ซิม ML integration และการหยิบ–วาง NOT RUN** แผนนี้ไม่ใช่ผลรับรองว่ามอเตอร์ราคาประหยัดผ่านงานวิจัยแล้ว
