## สรุปและข้อเสนอ (ผู้ตัดสินคือโรล C)

1. **ค่ามอเตอร์และ electronics ที่มีราคาเท่ากันทั้งสองทาง** เพราะใช้ชุด PWM เดียวกัน 7 ตัว (TD8120MG×2 + MG996R×4 + MG90S×1): **2,465 บาท** หรือ 2,565 บาทถ้าก้ามใช้ MG996R ต่างกันที่ filament สกรู ลูกปืน (ยังไม่ตีราคา) และเวลาออกแบบ
2. **แรงบิดไหล่คือตัวตัดสินหลัก** ที่ท่าเหยียดแนวนอนพร้อมบล็อก 100 g (ประมาณ):
   - AM-ARM200 + PWM: ไหล่ ≈ **30.7–32.6 kg·cm** สูงกว่าฉลากร้าน TD8120MG (18.5–21.8 kg·cm) ทั้งที่ฉลากนั้นน่าจะเป็นค่า stall แปลว่า**เปลี่ยนแค่มอเตอร์ไม่พอ** ต้องหดแขน เพิ่มเกียร์/มอเตอร์คู่ หรือชดเชยน้ำหนักด้วยสปริง
   - SO-101 + yaw + PWM: ไหล่ ≈ **14.9–16.3 kg·cm** ต่ำกว่าฉลากร้าน แต่สูงกว่าราว 1/3 ของ stall (Feetech เองให้ rated ≈ 1/3 ของ stall ใน STS3215/STS3095) จึง**ยังเสี่ยง ต้องวัดจริง**
3. **ซิม:** SO-101 มี MJCF พร้อม actuator และ joint limit อยู่แล้ว AM-ARM200 มีแค่ URDF ที่ effort/velocity = 0, limit ±3.14 placeholder และมวลลิงก์กล้อง 1.27 kg ที่น่าจะผิด
4. **CAD:** SO-101 มี STEP รายชิ้น + STEP ทั้ง assembly + โมเดล STS3215 และลิงก์ Onshape ต้นฉบับ (สิทธิ์ copy ยังไม่ชัด) AM-ARM200 มีเพียง STP รายชิ้น ชิ้นใหญ่กว่าและซับซ้อนกว่า
5. **ข้อได้เปรียบของ AM-ARM200:** ได้ข้อมือ 3 แกน (pitch–yaw–roll) ที่ออกแบบและประกอบแล้ว และเอื้อมไกลกว่า (≈528 vs ≈417 mm จากแกนไหล่) แต่ระยะเอื้อมนี้เป็นต้นเหตุที่ PWM รับโหลดไม่ไหว

**ข้อเสนอ: ทาง 2 (SO-101 + ข้อมือ yaw ที่ทีมออกแบบเอง)** ด้วยเหตุผลตามข้อ 2–4 ใช้ข้อมือ yaw ของ AM-ARM200 เป็นแบบอ้างอิงได้ เพราะเป็น Apache-2.0 ทั้งสอง repo (ต้องคง attribution/NOTICE) ทาง 1 เหมาะเมื่อทีมยอมใช้ bus servo ตามต้นฉบับ ซึ่งเกินงบ D24 (BOM ผู้สร้าง US$243.33) **การเลือกเป็นของโรล C** และทั้งสองทางต้องทดสอบแรงบิดไหล่จริงก่อนสั่งพิมพ์ชิ้นใหญ่

## 1. Kinematics

วิธี: parse joint origin/axis จาก [AM URDF](https://github.com/liyiteng/AM-ARM/blob/5b03af1ef6c80595bd988e0137cf8e7c35811eb6/am-arm200/urdf/urdf/am-arm200.urdf) และ [SO-101 MJCF old_calib](https://github.com/TheRobotStudio/SO-ARM100/blob/a758567c3978dfeefe282ede0500085a48fe8f78/Simulation/SO101/so101_old_calib.xml) (zero = เหยียดแนวนอน ตาม [Simulation README](https://github.com/TheRobotStudio/SO-ARM100/blob/a758567c3978dfeefe282ede0500085a48fe8f78/Simulation/SO101/README.md)) แล้วทำ forward kinematics และ grid search มุม pitch สามข้อหาท่าที่ปลายนิ้วไกลแนวนอนที่สุด ใช้ Python stdlib ไม่ได้รันซิม

**AM-ARM200 ลำดับข้อต่อ** shoulder_pan → shoulder_lift → elbow_flex → wrist_flex → **wrist_yaw** → wrist_roll → gripper (revolute ทั้งหมด) ตรงกับ motor list ใน [README](https://github.com/liyiteng/AM-ARM/blob/5b03af1ef6c80595bd988e0137cf8e7c35811eb6/README.md)

| ช่วง | ระยะ (mm) |
|---|---:|
| pan origin → shoulder_lift | 123.1 (ยกสูง 108.6, offset ด้านข้าง 58.0) |
| shoulder_lift → elbow (ระยะระหว่างแกน) | 134.9 |
| elbow → wrist_flex | 198.4 |
| wrist_flex → wrist_yaw → wrist_roll | 28.4 + 64.8 |
| wrist_flex → ปลายนิ้วก้ามตาย (vertex ไกลสุดของ `left_Fixed_Jaw.STL`) | 195.2 |
| **เอื้อมแนวนอนสูงสุด แกนไหล่ → ปลายนิ้ว** | **≈528** (จากแกน pan ≈586) |

ตัวเลข 528 mm สอดคล้องกับ "52 cm reach" ใน README แต่ไม่ได้ตรวจการชนกันเอง และ URDF ใช้ limit ±3.14 ทุกข้อ ระยะจริงจึงยังไม่ยืนยัน

**SO-101 ลำดับข้อต่อ** shoulder_pan → shoulder_lift → elbow_flex → wrist_flex → wrist_roll → gripper

| ช่วง | ระยะ (mm) |
|---|---:|
| shoulder_lift → elbow | 116.0 |
| elbow → wrist_flex | 135.0 |
| wrist_flex → wrist_roll | 63.7 |
| wrist_flex → site `gripperframe` / ปลายนิ้ว (mesh `wrist_roll_follower_so101_v1`) | 160.4 / 166.8 |
| **เอื้อมแนวนอนสูงสุด แกนไหล่ → ปลายนิ้ว** | **≈417** (จากแกน pan ≈447) |

ช่วงมุมใน MJCF: pan ±110°, lift −190°…+10° (old_calib), elbow −10°…+180°, wrist_flex ±95°, wrist_roll ±160°, gripper −10°…+100°

**จุดที่ต้องใส่ wrist yaw ใน SO-101:** ระหว่าง `wrist_flex` กับ `wrist_roll` ให้ลำดับเหมือน AM-ARM200 (pitch–yaw–roll) ใน MJCF body `wrist` คือชิ้น `Wrist_Roll_Pitch_SO101` ที่ถือเซอร์โว wrist_roll (`sts3215_03a_no_horn_v1`) ส่วน body `gripper` คือ `Wrist_Roll_Follower_SO101` + เซอร์โวก้าม การเพิ่ม yaw:
- `Wrist_Roll_Pitch` ต้องเปลี่ยนจากถือเซอร์โว roll เป็นถือเซอร์โว yaw (แกนตั้งฉากทั้ง pitch และ roll; ที่ zero pose pitch ≈ แกน x, roll ≈ แกน y ของ world จึงให้ yaw ≈ แกน z)
- ต้องเพิ่ม bracket ใหม่ถือเซอร์โว roll
- เซอร์โว roll, ก้าม และบล็อก ถูกดันออกไปไกลขึ้นตามความยาวชุด yaw อ้างอิงจาก AM: wrist_flex→roll = 93.2 mm เทียบ SO 63.7 mm (ยาวขึ้น ≈30 mm) การคำนวณแรงบิดด้านล่างสมมติ 50 mm เพื่อเผื่อ
- ต้องเดินสายผ่านข้อต่อเพิ่มหนึ่งข้อ

**ผลต่อการออกแบบ**

- **Path 1:** ต้องออกแบบช่องเซอร์โวใหม่ทั้ง **7 ช่อง** ช่อง STS3095 สามช่อง (pan, lift, elbow) ใหญ่และหนักกว่า PWM มาก (65×30×48 mm, 194.5 g เทียบ TD8120MG 40×20×40.5 mm, 65 g) ถ้าใส่ PWM ตามเดิมจะเหลือช่องว่างมาก และเปลือกที่หุ้ม STS3095 จะออกแบบใหม่ได้ทั้งชิ้น
- **Path 2:** ต้องออกแบบใหม่ **6 ช่องเดิม + ชุด yaw 1 ชุด** ขนาด STS3215 กับ MG996R ใกล้กัน (45.2×24.7×35 vs 40.7×19.7×42.9 mm) แต่ MG996R มีปีกยึด ส่วน STS3215 ไม่มี
- **Horn:** ทุกชิ้นที่ยึดกับ horn ต้องเปลี่ยน pattern ทั้งสองทาง STS3215 ใช้ horn โลหะ 4-M3 บนวง Ø14 และ STS3095 ใช้ 15T ส่วน horn ของ PWM เป็นอีกแบบ
- **Dual shaft:** STS3215 และ STS3095 เป็น dual shaft ข้อต่อ SO-101 ข้อ 1–4 และก้ามใช้ "bottom horn" เป็นจุดรับด้านตรงข้าม ([คู่มือ HF](https://huggingface.co/docs/lerobot/so101)) MG996R/TD8120MG มีเพลาเดียว จึงต้องเพิ่มลูกปืน + pin ทุกข้อต่อแบบ clevis ทั้งสองทาง AM มีแบบ pin + ลูกปืน 12×18×4 ที่ J5 ให้ดูเป็นตัวอย่าง

## 4. แรงบิดค้างตัว (estimate, ไม่ใช่ผลวัด)

**บล็อก (ประมาณ):** ไม้ทั่วไปความหนาแน่นราว 0.35–0.75 g/cm³ เป็นช่วงประมาณ ยังไม่ได้ตรวจตารางรายพันธุ์ไม้ใน [USDA Wood Handbook](https://www.fpl.fs.usda.gov/documnts/fplgtr/fplgtr282/fpl_gtr282.pdf) = unverified
- ลูกบาศก์ 4 ซม. (64 cm³) ≈ 22–48 g
- ลูกบาศก์ 5 ซม. (125 cm³) ≈ 44–94 g
- **ใช้ 100 g** และวางที่ปลายนิ้ว ซึ่งไกลกว่าจุดจับจริง (conservative)

**วิธีคำนวณ:** τ = Σ mᵢ·g·dᵢ โดย dᵢ คือระยะแนวนอนจากแกนข้อต่อถึง COM ที่ท่าเหยียดแนวนอน ใช้ COM/มวลจาก URDF/MJCF และให้เซอร์โวเป็นมวลจุดที่แกนข้อต่อที่มันขับ (สมมติ) แปลงหน่วยด้วย 1 kg·cm = 0.0981 N·m

**ข้อควรระวังเรื่องมวลในโมเดล**
- **AM URDF:** มวลลิงก์ ≈ ปริมาตร mesh × ~0.94–1.0 g/cm³ (เช่น Upper_Arm 0.2639 kg / 282 cm³; ยกเว้น wrist_yaw 0.74 g/cm³) จึงดูเป็นค่าความหนาแน่นเดียวจาก SolidWorks ไม่ใช่มวลเซอร์โวจริง (STS3095 หนัก 194.5 g)
- **ลิงก์ `left_camera` ของ AM:** มวล 1.271 kg จาก mesh ราว 19 cm³ น่าจะเป็นความผิดพลาดของ export จึง**ตัดออก**
- **SO-101 MJCF:** body รวม geometry ของ STS3215 ไว้ด้วย ([so101_new_calib.xml](https://github.com/TheRobotStudio/SO-ARM100/blob/a758567c3978dfeefe282ede0500085a48fe8f78/Simulation/SO101/so101_new_calib.xml)) แต่ยังไม่ได้ยืนยันว่ามวลรวมมวลเซอร์โวจริงไว้ = unverified

**Path 1: AM-ARM200 + PWM (TD8120MG ที่ lift/elbow, MG996R ที่ pan/wrist×3, ก้าม MG90S)**

ระยะแนวนอนจากแกนไหล่ (mm): elbow 134.9, wrist_flex 333.3, yaw 361.4, roll 424.8, gripper 447.1, ปลายนิ้ว 528.3

- โครงตาม URDF ไม่รวมบล็อก: ไหล่ 1.749 N·m, ศอก 0.885 N·m
- บล็อก 0.1 kg: ไหล่ 0.1×9.81×0.5283 = 0.518 N·m, ศอก 0.1×9.81×0.3934 = 0.386 N·m
- เซอร์โวที่ไหล่ต้องยก: 9.81×(0.065×0.1349 + 0.055×0.3333 + 0.055×0.3614 + 0.055×0.4248 + 0.0134×0.4471) = 0.749 N·m
- เซอร์โวที่ศอกต้องยก: 9.81×(0.055×0.1984 + 0.055×0.2265 + 0.055×0.2899 + 0.0134×0.3125) = 0.427 N·m
- **รวมไหล่ ≈ 3.02 N·m ≈ 30.7 kg·cm** (ก้าม MG996R: 32.6) **รวมศอก ≈ 1.70 N·m ≈ 17.3 kg·cm** (18.6)
- เปรียบเทียบชุด STS เดิมด้วยวิธีเดียวกัน: ไหล่ ≈ 34.4 kg·cm เทียบ STS3095 rated 22.5 kg·cm @7.4V และ stall 95 kg·cm ([datasheet](https://www.feetechrc.com/Data/feetechrc/upload/file/20260622/6391772399568934299631399.pdf)) **แบบนี้จึงออกแบบรอบ STS3095** การเปลี่ยนเป็น PWM ลดมวลเซอร์โวได้ (194.5→65 g ที่ศอก) แต่แรงบิดที่มอเตอร์ให้ได้ลดลงมากกว่ามาก

**Path 2: SO-101 + yaw + PWM (ชุดเดียวกัน)**

ระยะแนวนอนจากแกนไหล่ (mm): elbow 116.0, wrist_flex 251.0, roll 312.5, gripper 336.4, ปลายนิ้ว 410.8

- MJCF + บล็อก 0.1 kg (5 แกน): ไหล่ 1.266 N·m (12.9 kg·cm), ศอก 0.741 N·m (7.6 kg·cm)
- เปลี่ยนเซอร์โว: MG996R 55 g = STS3215 55 g จึงไม่เปลี่ยน; TD8120MG ที่ศอก +10 g × 0.116 m = +0.011 N·m ต่อไหล่; ก้าม MG90S −41.6 g = −0.137 N·m ต่อไหล่ และ −0.090 N·m ต่อศอก
- เพิ่ม yaw (สมมติ): MG996R 55 g + bracket 25 g ที่ wrist_flex + 30 mm และดันมวลปลาย (gripper 0.087 + jaw 0.012 + บล็อก 0.1 = 0.199 kg) ออกไป 50 mm
  - ไหล่ +0.08×9.81×0.281 + 0.199×9.81×0.05 = +0.318 N·m
  - ศอก +0.08×9.81×0.165 + 0.0976 = +0.227 N·m
- **รวมไหล่ ≈ 1.46 N·m ≈ 14.9 kg·cm** (ก้าม MG996R: 16.3) **รวมศอก ≈ 0.88 N·m ≈ 8.9 kg·cm** (9.9)

**เทียบกับค่าที่มอเตอร์ระบุ**

| | ค่าที่ระบุ | Path 1 ต้องการ | Path 2 ต้องการ |
|---|---|---|---|
| ไหล่ TD8120MG | 18.5–21.8 kg·cm (ฉลากร้าน ไม่ระบุว่าเป็น stall หรือ continuous และไม่แยกตามแรงดัน) | 30.7–32.6 → **เกิน** | 14.9–16.3 → ต่ำกว่าฉลาก แต่ใช้ฉลากไปราว 70–75% |
| ศอก TD8120MG | เหมือนข้างบน | 17.3–18.6 → ใกล้ฉลาก | 8.9–9.9 |
| wrist_flex MG996R | 11 kg·cm stall @6V ([TowerPro](https://towerpro.com.tw/product/mg996r/)) | ≈4.7 kg·cm | ≈2.8 (5 แกน) / ≈4 (มี yaw) |

Feetech ให้ rated ≈ 1/3 ของ stall (STS3215 12V: 10/30; STS3095: 22.5/95) ซึ่งเป็นบริบทสำหรับมอเตอร์ของ Feetech เท่านั้น **ไม่ใช่สเปก TD8120MG** ถ้าใช้สัดส่วนนี้กับ TD8120MG ด้วย ทั้งสองทางจะเกินที่ไหล่ Path 2 จึง "เสี่ยงน้อยกว่า" ไม่ใช่ "ผ่าน"

ข้อต่อ base pan เป็นแกนตั้ง จึงไม่มีโหลดค้างจากแรงโน้มถ่วง มีเพียงโหลดจากความเฉื่อย (ไม่ได้คำนวณ) ทุกตัวเลขในส่วนนี้ **NOT RUN** และต้องวัดกระแส/อุณหภูมิในท่าค้างก่อนใช้ตัดสิน

## 5. ความพร้อมซิม MuJoCo (Windows)

**AM-ARM200** มี [URDF](https://github.com/liyiteng/AM-ARM/blob/5b03af1ef6c80595bd988e0137cf8e7c35811eb6/am-arm200/urdf/urdf/am-arm200.urdf) ไฟล์เดียว สร้างจาก SolidWorks exporter ไม่มี MJCF
- mesh path เป็น `package://am-arm200/am-arm200-meshes/...` แต่ mesh อยู่ที่ `am-arm200/urdf/am-arm200-meshes/` ต้องแก้ path ให้ MuJoCo หาเจอ (MuJoCo จัดการ `package://` อย่างไร = unverified)
- ทุก joint มี effort = 0, velocity = 0, limit ±3.14 ซึ่งเป็น placeholder ไม่มี actuator
- มวลเป็นค่าความหนาแน่นเดียว และลิงก์กล้องมวล 1.27 kg ที่น่าจะผิด (§4)
- collision ใช้ mesh เต็ม เช่น `left_wrist_yaw.STL` 252k triangles อาจต้องลดรายละเอียด
- zero pose เป็นท่าพับ ไม่ใช่ท่าเหยียด
- ก้ามเป็น revolute jaw เดียว ใช้ได้
- **งานที่ต้องทำ:** แก้ path, ตั้ง limit จริง, ใส่มวล/inertia ของเซอร์โว PWM และชิ้นที่ออกแบบใหม่, เขียน MJCF + actuator + scene, ทำ collision ให้ง่ายลง และ mesh/frame ต้องตรงกับชิ้น PWM ที่ออกแบบใหม่ทั้ง 7 ช่อง

**SO-101** มี [URDF/MJCF](https://github.com/TheRobotStudio/SO-ARM100/tree/a758567c3978dfeefe282ede0500085a48fe8f78/Simulation/SO101) สร้างด้วย onshape-to-robot
- mesh path เป็นแบบ relative (`meshdir="assets"`) และมี `scene.xml`
- มี actuator แบบ position (class `sts3215`, `forcerange ±3.35`) และ limit จริง
- มี backlash class และปรับพารามิเตอร์ล่าสุดใน [#141](https://github.com/TheRobotStudio/SO-ARM100/pull/141) (2025-11-27)
- ข้อจำกัดตาม README: ไม่มี collision mesh ที่ base, ไม่มี gripper mapping 0–100 ของ LeRobot (ไม่จำเป็นสำหรับเรา) และ [issue #146](https://github.com/TheRobotStudio/SO-ARM100/issues/146) แจ้งว่า URDF มี setting เก่า
- **งานที่ต้องทำ:** แทรก body `wrist_yaw` + joint + mesh ระหว่าง `wrist` กับ `gripper`, เปลี่ยน mesh ช่องเซอร์โวเป็นแบบ PWM, เปลี่ยน kp/forcerange/armature จาก STS3215 เป็นค่าประมาณของ PWM (ไม่มีข้อมูลผู้ผลิตให้ fit) และแก้มวล

**สรุป:** Path 2 เริ่มจากโมเดลที่ใช้งานได้แล้วแก้บางส่วน Path 1 ต้องสร้าง MJCF ใหม่เกือบทั้งหมด ยังไม่ได้ลองโหลดบน Windows ทั้งสองทาง (NOT RUN)

## 10. งานออกแบบที่ต้องทำ (เชิงคุณภาพ ไม่ประเมินชั่วโมง)

**Path 1: AM-ARM200 → PWM**
1. ออกแบบช่องเซอร์โวใหม่ 7 ช่อง ในชิ้น J1_Base, J2_Rotation, J3_Shoulder, J4_Elbow, J5/J56 และ J7_Gripper (ชิ้นที่ถือเซอร์โวไหนต้องยืนยันจาก STP)
2. เปลี่ยน interface horn ทุกข้อต่อ และเพิ่มลูกปืน/pin แทนเพลาหลัง
3. **แก้ปัญหาแรงบิดไหล่ (ใหญ่ที่สุด):** หดแขนส่วนบน/ล่าง หรือเพิ่มมอเตอร์คู่/เกียร์ทด/สปริงชดเชย ซึ่งเปลี่ยน kinematics ของแบบ
4. ตรวจช่วงมุม MG996R (TowerPro ตอบว่า 0–159°) กับช่วงที่ข้อต่อต้องใช้
5. สร้าง MJCF ใหม่: path, limit, มวลเซอร์โว, actuator และแก้ลิงก์กล้อง
6. ซ่อมเอกสาร BOM/ประกอบของเวอร์ชันทีม

**Path 2: SO-101 + yaw → PWM**
1. ออกแบบช่องเซอร์โวใหม่ 6 ช่อง ใน Base/Base_motor_holder, Motor_holder_Base, Rotation_Pitch, Upper_arm, Under_arm/Motor_holder_Wrist, Wrist_Roll_Pitch และ Wrist_Roll_Follower/Moving_Jaw
2. ออกแบบชุดข้อมือ yaw ใหม่: แบ่ง Wrist_Roll_Pitch เป็นส่วนถือเซอร์โว yaw + bracket ถือเซอร์โว roll, เดินสาย และตรวจไม่ให้ชนตลอดช่วงมุม อ้างอิงข้อมือ AM-ARM200 ได้
3. เปลี่ยน interface horn และเพิ่มลูกปืน/pin แทน bottom horn (ข้อ 1–4 + ก้าม)
4. ตรวจแรงบิดไหล่เมื่อแบบเสร็จ เพราะชุด yaw เพิ่มโหลด (§4) และพิจารณาสปริงชดเชยถ้าวัดแล้วไม่พอ
5. แก้ MJCF: แทรก body `wrist_yaw`, เปลี่ยน mesh/มวล/actuator class
6. ตรวจช่วงมุม MG996R กับ pan ±110° และ roll ±160° ของแบบเดิม

## คำถามเปิด

1. บล็อกจริงหนักกี่กรัม (ชั่งจริง) และต้องเอื้อมไกลเท่าไร ถ้าระยะ ≈30 ซม. พอ ทั้งสองทางหดแขนได้และแรงบิดลดลงตามระยะ
2. ฉลาก TD8120MG 18.5–21.8 kg·cm เป็น stall ที่แรงดันใด และค่าต่อเนื่องเท่าไร ต้องหาสเปกผู้ผลิตหรือวัดเอง
3. ยอมรับการเพิ่มสปริงชดเชยน้ำหนัก (gravity compensation) ที่ไหล่ได้หรือไม่ ถ้าได้ อาจทำให้ Path 1 กลับมาเป็นไปได้
4. MG996R ล็อตร้านหมุนได้กี่องศาจริง (ผู้ผลิตตอบ 0–159° แต่ร้านอ้าง 180°) พอกับ pan และ wrist roll หรือไม่
5. MG90S มีแรงจับพอสำหรับบล็อก 100 g หรือไม่ หรือต้องใช้ MG996R (+100 บาท)
6. PSU 5V 10A พอกับกระแส stall รวมหรือไม่ และต้องมีวิธีหยุดฉุกเฉินแบบใด
7. ต้องขอสิทธิ์ copy Onshape ของ SO-101 หรือใช้ STEP ก็พอ (ไม่ได้ติดต่อใคร)
