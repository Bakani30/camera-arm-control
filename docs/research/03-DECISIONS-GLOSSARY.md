## สิ่งที่ไม่ควรนำจากบทสนทนาเก่ามาเป็นข้อกำหนด
- งบ 6,000 บาทถูกแทนด้วย 10,000 บาท
- มือเดียวไม่ได้แปลว่าไม่อยากมีสองมือ แต่สองมือถูกย้ายเป็นส่วนต่อยอด
- AI ตั้งค่าเอกสารเคยยืนยันก่อนเปลี่ยนเจตนา จึงไม่อยู่ใน scope ล่าสุด
- UR5e+LEAP และ MuJoCo ยังไม่ผ่านการพิสูจน์ใช้งานร่วมกัน
- คำกล่าวว่ามีเวลามากจึงทำได้ครบเป็นเพียงการประเมิน ไม่ใช่ guarantee
- เปิดโค้ดไม่ได้หมายความว่าต้องสร้าง product ecosystem หรือ dataset platform

## คำศัพท์ที่ใช้ร่วมกัน
- Teleoperation: คนควบคุมการทำงานของหุ่นยนต์ต่อเนื่อง ไม่ได้แปลว่าต้องอยู่ผ่านอินเทอร์เน็ต
- Hand tracking: การติดตามมือจากภาพ ไม่ใช่การคำนวณข้อต่อหุ่นยนต์
- Retargeting: แปลงท่าหรือเจตนาการเคลื่อนไหวจากคนไปโครงสร้างหุ่นยนต์
- IK: คำนวณมุมข้อต่อเพื่อให้ปลายแขนไปยังเป้าหมาย อาจไม่มีคำตอบหรือมีหลายคำตอบ
- End effector: ส่วนปลายที่ทำงาน เช่น gripper หรือมือกล
- DOF: องศาอิสระของการเคลื่อนที่ จำนวนมอเตอร์รวมก้ามหนีบไม่เท่ากับ DOF ของแขนเสมอ
- Profile: ค่าตั้งและ mapping เฉพาะรุ่น ไม่ใช่ learned model
- Adapter: ส่วนสื่อสารซิม/ฮาร์ดแวร์ ไม่ได้สร้างได้จากไฟล์รูปร่างอย่างเดียว
- Calibration: การหาจุดอ้างอิง สัดส่วน เฟรม หรือ offset
- RGB monocular: กล้องสีตัวเดียว ประมาณความลึกได้แต่ไม่ได้วัดระยะจริงโดยตรง
- Smoothness: ความต่อเนื่องของการเคลื่อนไหว ต้องพิจารณาคู่กับ error/latency
- Real-time: ตอบสนองทันข้อกำหนดการควบคุม ต้องวัดทั้งวงจร ไม่ใช่ดู FPS อย่างเดียว
- Multi-model support: ใช้ระบบกับหลายโมเดลผ่านค่าตั้ง/ตัวเชื่อมต่อ
- Cross-embodiment generalization: โมเดลเรียนรู้ใช้กับโครงสร้างใหม่ที่ไม่ใช้ฝึก เป็นข้ออ้างที่เข้มกว่า multi-model support
- Residual: ค่าปรับเพิ่มเติมจากคำสั่ง baseline
- Imitation learning: เรียนพฤติกรรมจากตัวอย่าง ไม่ใช่เป้าหมายหลักให้หุ่นยนต์ทำงานเองในโครงการนี้
- Ground truth: ค่าอ้างอิงที่มีวิธีได้มาชัดเจน ผล AI ตัวอื่นไม่เป็น ground truth อัตโนมัติ
- Held-out: ข้อมูลหรือโมเดลที่กันจากการฝึก/ปรับค่า ระบุว่ากันระดับไหน
- แบบอ้างอิงแขนจริง (Arm reference): แหล่งความจริงของรูปร่างและตัวเลขแขนจริง ก่อนประกอบคือ CAD ของทีมกับ datasheet มอเตอร์ หลังประกอบคือค่าวัดจากแขนจริงซึ่งชนะทุกแหล่ง; URDF/MJCF ต้นฉบับของ SO-101 เป็นแค่จุดเริ่มต้น ถ้าขัดกับ CAD ให้ CAD ชนะ
- สเปกแขนจริง (Arm spec): ตัวเลขที่ดึงจากแบบอ้างอิงแขนจริงพร้อมเทสต์ตรวจรับ ใช้ตัดสินว่าโมเดลจำลองเหมือนแขนจริงหรือไม่ โรล C เป็นเจ้าของ โมเดลจำลองของ B ต้องผ่านเทสต์นี้
- โมเดลนำเสนอ (Presentation model): โมเดล 3 มิติบนเว็บและวิดีโอที่ใช้ในสไลด์ เน้นรูปทรงตรงแบบอ้างอิงและการเคลื่อนไหวสมจริง เล่นเดโมตามสคริปต์ ไม่ใช่ซิมฟิสิกส์ และไม่ใช่หลักฐานผลทดลอง
- แฝดซิม (Sim twin): โมเดล MuJoCo ของแขนจริงที่ B ดูแล ใช้ทดลองและเทียบผลกับแขนจริง ต้องผ่านเทสต์ของสเปกแขนจริง ต่างจากโมเดลนำเสนอ
- การเคลื่อนไหวสมจริง (Motion realism): ในโมเดลนำเสนอหมายถึงครบ 5 ข้อ: ความเร็วและการเร่งแบบเซอร์โวจริง, ไม่มีท่าที่เป็นไปไม่ได้ (เกินขีดจำกัด ทะลุโต๊ะหรือตัวเอง), ทำงานจริงให้เห็น, ก้ามหนีบแล้วของติดไปด้วย, ฐานหันไปหาเป้าหมาย

  - แก้ไข 2026-10-31: ตัวเลข "หยิบตรงลงที่ TCP 10 ซม. ได้ 12–25 ซม." ไม่ถูกต้อง ท่าก้มตรงลงที่ TCP สูง 10 ซม. ต้องใช้ `wrist_flex` ~99–111° จึงเกิน ±95° และเอื้อมไม่ถึงตั้งแต่ ~24 ซม. (ดู hardware-notes/2026-10-31-motion-test-results.md) การเลือก STS3215 ยังใช้ได้ด้วยเหตุผลเรื่องอ่านมุมกลับ
- D37 / 2026-10-31 / ยืนยัน
  - ปัญหา: spec v0 ใช้ TCP และข้อก้ามของ SO-101 ซึ่งไม่ตรงก้ามที่ออกแบบเอง ทดสอบมูฟบน CAD แล้วนิ้วชนบล็อก, กดปุ่มลึกเกิน, นิ้วชนเสาไหล่ และ 23% ของท่าที่ soft limit ยอมให้ไปชนโต๊ะหรือฐาน
  - ข้อสรุป: spec v1 ตามตารางข้อสรุปด้านบน; spec v0 คงไว้เป็นค่าอ้างอิง SO-101
  - ผู้ยืนยัน: ผู้ใช้ (โรล C) สั่งทำ spec v1 จากผลทดสอบ
  - ผลต่อการทำงาน: B ใช้ `tcp_xyz_for_opening` และ `crank_rad` ในโมเดลซิม; ข้อต่อแขนทั้ง 5 ข้อไม่เปลี่ยน; มวลยังเป็นค่าประเมิน ยังไม่ slice หรือชั่ง
- D38 / 2026-10-31 / ยืนยัน
  - ปัญหา: ท่อกลม Ø37 เล็กกว่าหน้าตัด STS3215 ตัว servo จึงทะลุผนังท่อทั้งสองปลาย
  - ตัวเลือก: A เสื้อเหลี่ยมมนปิดมิด / B ท่อกลมใหญ่ขึ้น / C กรอบพร้อมช่องเปิด
  - ข้อสรุป: แบบ C หลังแก้ครีบ ขอบช่อง สกรู และร่องระบายอากาศ
