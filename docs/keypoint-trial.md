# ทดลองตัวจำแนก Kazuhito ที่ปรับเข้ากับโปรเจกต์

สถานะ: ทางเลือกทดลอง ยังไม่แทนค่าเริ่มต้น MediaPipe และยังไม่ยืนยันความแม่นยำบน ASUS
แหล่งโค้ด/โมเดลและ license: ../third_party/kazuhito/NOTICE.md และ source.json

ใช้ MediaPipe Tasks ของเราอ่านจุดมือ แล้วใช้วิธี upstream แปลงเป็นพิกัด pixel เทียบข้อมือและหารด้วยขนาดสูงสุดก่อนส่งโมเดล TFLite เดิมของผู้สร้าง ไม่ใช่การรัน upstream app ทั้งชุด detector ต่างจาก legacy API ของต้นฉบับ จึงต้องวัดผลจริง

โมเดลมีเพียง Open/Close/Pointer ไม่มีคลาสอื่นแบบครอบคลุม จึงอาจเดาท่าอื่นเป็นหนึ่งในสามท่า คะแนนไม่ใช่หลักฐานความถูกต้อง โมเดลนี้ไม่วัดระยะจริง และ normalization ไม่แก้มือหลุด/เบลอ/การบัง

## Windows: environment ทดลองแยกจากตัวเดิม
```powershell
py -3.11 -m venv .venv-keypoint
.\.venv-keypoint\Scripts\python.exe -m pip install -r requirements-keypoint.txt
.\.venv-keypoint\Scripts\python.exe -m camera_gestures.download_keypoint
.\.venv-keypoint\Scripts\python.exe -m camera_gestures.app --classifier keypoint
```
ต้องมีโมเดล MediaPipe เดิมด้วย หากยังไม่มีให้รัน camera_gestures.download_model

บนเครื่อง Mac ที่เตรียมทดลองในเซสชั่นนี้:
```sh
/tmp/camera-kazuhito-test/.venv/bin/python -m camera_gestures.app --classifier keypoint
```

## วิธีทดลอง
แบ/กำ/ชี้ ทีละท่า เลื่อนมือใกล้–กลาง–ไกลโดยยังเห็นครบมือและข้อมือ ดูผล keypoint กับ MediaPipe บนภาพเดียวกัน กด 1/2 กำกับแบ/กำ; ชี้และท่าอื่นกด 0 (Other) ตามระบบป้ายเดิม ไม่ใช่ชุดข้อมูลฝึก 3 คลาสสำเร็จ
ทดสอบแสงและมุมคงที่ก่อน บันทึกระยะวัดจริงแยกต่างหากถ้าต้องการรายงานเซนติเมตร
JSONL เพิ่ม classifier, mediapipe_gesture/score และ keypoint_ms เวลา inference_ms เป็น MediaPipe เท่านั้น ระบุแยกเพื่อเปรียบเทียบ ไม่ใช่ latency ทั้งระบบ
รหัสควบคุมยังใช้กติกาคงค่าของทีม: ท่าชี้อาจคง 01/10 ล่าสุดขณะยังพบมือ ไม่มีรหัสควบคุมใหม่สำหรับชี้นิ้ว ห้ามเชื่อมฮาร์ดแวร์จากรุ่นทดลอง

## กรอบมือและเป้าหมายข้อมือ
กรอบระบุ OPEN/FIST/POINT หรือ UNKNOWN ตามผลปัจจุบันและ threshold ไม่ใช้รหัสที่ค้างมาเป็นชื่อท่า ไม่มีมือหรือ stale จะลบกรอบ
พื้นที่ขวาเป็นพิกัดจอ 2D ไม่ใช่พิกัดหุ่นยนต์หรือเมตร: ขวาเป็น +x ลงเป็น +y ตามภาพกระจก
- C: ตั้งข้อมือปัจจุบันเป็นจุดอ้างอิงและเริ่มตาม จากตำแหน่งเป้าหมายเดิม จึงไม่กระโดดตอนเริ่ม
- Space: พัก; กด C ใหม่เพื่อเริ่มต่อ
- มือหาย ผล stale เปลี่ยนซ้าย/ขวา หรือข้อมูลเว้นเกิน 500 ms: พัก ต้องกด C ใหม่
- จุดสีฟ้า: เป้าหมายผ่านตัวกรองเวลา 80 ms; วงเหลือง: เป้าหมายดิบ
- วงกลมเทา: จุดฝึกเลื่อนเป้าหมายเข้าไปค้าง ยังไม่มีระบบให้คะแนนอัตโนมัติ
- JSONL เก็บ screen_target, screen_raw และ target_active ทุกเฟรม
- ชื่อท่า/คะแนนเป็นผลโมเดล ยังอาจทายผิดแม้คะแนนสูง
ทดสอบ C แล้วเลื่อนครบสี่ทิศ ค้างนิ่ง พักและเริ่มใหม่ นำมือออกและกลับเข้า ต้องไม่เริ่มเอง ก่อนเข้าสู่ซิม

## แกนเข้า–ออก (ทดลอง)
C ตั้งขนาดฝ่ามืออ้างอิงพร้อมแกน XY; ค่า depth บวกคือเข้าใกล้กล้อง ลบคือออกห่าง เป็น proxy ไม่มีหน่วยเมตร ใช้ค่าเฉลี่ยเรขาคณิตของระยะ pixel ระหว่างโคนนิ้วชี้–ก้อย และข้อมือ–โคนนิ้วกลาง แทนปลายนิ้ว
สูตร anchor + 1 - reference/current จำกัด [-1,1] กรองตามเวลา 120 ms การกด C ใหม่รักษาค่าปัจจุบัน ไม่กระโดดกลับศูนย์
Space/มือหาย/stale/เปลี่ยนมือ/เฟรมเว้นนานพักเหมือน XY; ถ้าจุดฝ่ามือผิดปกติ depth พักแยก ต้อง C ใหม่
ทดสอบแบมือหันเข้ากล้อง กด C เลื่อนเข้า–ออกช้า ๆ แล้วค้างนิ่ง จากนั้นกำ–แบโดยไม่เลื่อนข้อมือและเอียงมือเพื่อวัด false depth อย่าถือว่าการกรองแก้ perspective ได้ ต้องรายงานข้อจำกัดก่อนเชื่อมแกนลึกกับแขน
JSONL เพิ่ม palm_scale_px, depth_reference_px, depth_raw, depth_relative, depth_active

## การผูกมือและกลับมาตามต่อ (ข้อกำหนดล่าสุด แทนพฤติกรรมรอกด C หลังมือหายด้านบน)
ใช้คนเดียว กล้องตรวจสูงสุดสองมือ แต่เลือกเฉพาะด้านที่กำหนด ค่าเริ่ม Right; CLI --hand Left หรือ --hand Right
- L เลือกมือซ้าย / H เลือกมือขวา: พักและล้างรหัส gesture เดิม ต้อง C ก่อนเริ่มมือใหม่
- C ตั้งอ้างอิง XYZ พร้อมกัน ณ มือปัจจุบัน รักษาเป้าหมายเดิม ถ้ายังไม่มีมือให้รอแล้วเริ่มเมื่อข้อมูลครบ
- มือหาย/จุดฝ่ามือใช้ไม่ได้/stale: ค้าง XYZ เดิม
- มือที่เลือกกลับมาและข้อมูลใช้ได้: ตั้งอ้างอิงใหม่จากเฟรมแรกทันที XYZ ไม่กระโดด ไม่ต้อง C ซ้ำ
- R คืนเป้าหมายกลางจอ (.5,.5) และ depth=0 พร้อมเริ่มอ้างอิงใหม่ ถ้าไม่มีมือให้รอ
- Space พักด้วยผู้ใช้ ไม่ auto-resume จน C/R
ใช้คะแนน handedness >=.8; ไม่มีมือด้านที่เลือกหรือมีหลายมือด้านเดียวกันให้รอ ไม่ใช้มืออีกข้างแทน การเลือกด้านไม่ใช่การยืนยันบุคคล และโมเดลอาจจำแนกด้านผิดได้ ยังไม่รองรับหลายคน
ทดสอบ: เลื่อน XYZ ออกจากศูนย์ เอามือออก กลับมาสูง/ต่ำ/ใกล้กว่าเดิม เป้าหมายต้องอยู่เดิมในเฟรมกลับเข้า จากนั้นขยับแล้วตามได้ ทดสอบมืออีกข้างอย่างเดียวต้องไม่ตาม และ Space ต้องไม่เริ่มเอง
