# ภาษากลาง v0.1 (ร่าง)
สถานะ: **ร่างสำหรับสัปดาห์ 0** · เจ้าของ: โรล C · ทั้งทีมร่วมแก้ได้ถึงวันพุธ 28 ต.ค. แล้ว C ล็อกเป็น v0.1 · หลังล็อก เปลี่ยนได้เฉพาะวันจันทร์และต้องขึ้นเลขเวอร์ชัน

สัญญานี้คือสิ่งเดียวที่ทุกเลนต้องตกลงร่วมกัน ถ้าทุกเลนพูดภาษานี้ตรงกัน แต่ละเลนก็ทดสอบด้วยของจำลองได้โดยไม่ต้องรอกัน

```
A: กล้อง → mapping ──[ภาษากลาง 1: EndEffectorTarget]──▶ B: โปรไฟล์ + IK
B: โปรไฟล์ + IK ──[ภาษากลาง 2: JointCommand]──▶ ตัวแปลซิม (B) / ตัวแปลแขนจริง (C)
ตัวแปลซิม / แขนจริง ──[RobotState]──▶ logger, UI, การวัดผล
```

## 1. Convention ที่ใช้ทุกข้อความ
| เรื่อง | ข้อตกลง |
|---|---|
| หน่วย | เมตร, เรเดียน, วินาที (เวลาเก็บเป็นมิลลิวินาที) · ค่าจับเป็นสัดส่วน 0–1 |
| แกนหุ่นยนต์ `robot_base` | มือขวา: x ไปหน้า, y ไปซ้าย, z ขึ้น (ตาม ROS REP-103) จุดกำเนิดที่ฐานแขน |
| แกนกล้อง `camera` | ตาม OpenCV: x ขวา, y ลง, z ออกจากกล้อง ใช้ภายในเลน A เท่านั้น |
| Quaternion | ลำดับ `[w, x, y, z]` (ตาม MuJoCo) ชื่อฟิลด์ลงท้าย `_wxyz` เสมอ ต้อง normalize แล้ว |
| เวลา | `t_ms` = นาฬิกา monotonic ของเครื่องที่ส่ง หน่วยมิลลิวินาที (`time.monotonic_ns() / 1e6`) ใช้วัดช่วงเวลา ไม่ใช่เวลาจริง |
| ลำดับ | `seq` เป็นจำนวนเต็ม เพิ่มทีละ 1 ต่อผู้ส่งหนึ่งราย ใช้ตรวจข้อความหายหรือซ้ำ |
| ค่าจับ | `grip` 0 = เปิดสุด, 1 = ปิดสุด |
| ข้อต่อ | อ้างด้วยชื่อเสมอ ไม่ส่งอาร์เรย์มุมที่ไม่รู้ลำดับ ชื่อมาจากโปรไฟล์ของ B |
| รูปแบบไฟล์ | JSON Lines: หนึ่งบรรทัดหนึ่งข้อความ บรรทัดแรกของไฟล์เป็น header |

ทุกข้อความมีฟิลด์ `contract` บอกชนิดและเวอร์ชัน เช่น `"ee_target/0.1"` ผู้รับต้องปฏิเสธข้อความที่ major version ไม่ตรง

## 2. ภาษากลาง 1 — `EndEffectorTarget` (A → B)
"อยากให้ปลายก้ามไปอยู่ตรงนี้ หันทางนี้ หนีบเท่านี้" ยังไม่รู้ว่าเป็นแขนรุ่นไหน

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `contract` | str | `"ee_target/0.1"` |
| `t_ms` | float | เวลาที่สร้างเป้าหมาย |
| `seq` | int | ลำดับ |
| `robot_id` | str | โปรไฟล์ที่เป้าหมายนี้สเกลไว้ให้ เช่น `"small_arm"`, `"industrial_sim"` |
| `frame` | str | `"robot_base"` เท่านั้นใน v0.1 |
| `position_m` | [float, float, float] | ตำแหน่งปลายก้าม |
| `orientation_wxyz` | [float×4] หรือ `null` | `null` = ไม่สั่งการหมุน ให้ B คงทิศเดิม |
| `grip` | float | 0–1 |
| `mode` | str | `"track"` ตามมือ · `"hold"` พัก เป้าหมายค้าง · `"fine"` โหมดละเอียด |
| `enabled` | bool | `false` = ห้ามขยับ ผู้รับต้องหยุดเหมือนได้รับคำสั่งพัก |
| `source` | str | `"live"` · `"replay"` · `"script"` |

ตัวอย่าง:
```json
{"contract":"ee_target/0.1","t_ms":1523004.2,"seq":812,"robot_id":"small_arm","frame":"robot_base","position_m":[0.18,0.02,0.09],"orientation_wxyz":null,"grip":0.35,"mode":"track","enabled":true,"source":"live"}
```

## 3. ภาษากลาง 2 — `JointCommand` (B → ตัวแปล)
"ข้อไหล่ 0.52 rad, ข้อศอก −1.1 rad …" รู้รุ่นแขนแล้ว แต่ยังไม่รู้ว่าเป็นซิมหรือของจริง

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `contract` | str | `"joint_cmd/0.1"` |
| `t_ms`, `seq` | float, int | เหมือนข้อ 2 |
| `robot_id` | str | ต้องตรงกับโปรไฟล์ที่ตัวแปลโหลดอยู่ |
| `profile_version` | str | เวอร์ชันโปรไฟล์ เช่น `"small_arm/0.1"` ไม่ตรงให้ปฏิเสธ |
| `joints_rad` | {ชื่อ: float} | ทุกข้อต่อในโปรไฟล์ ห้ามขาดหรือเกิน |
| `grip` | float | 0–1 ตัวแปลแปลงเป็นค่าของก้ามเอง |
| `max_age_ms` | float | คำสั่งที่อายุเกินนี้ให้ถือว่าเก่า ค่าเริ่มต้นเสนอ 200 |
| `enabled` | bool | เหมือนข้อ 2 |
| `ik_ok` | bool | `false` = IK หาคำตอบไม่ได้หรือเป้าหมายเกิน workspace ห้ามขยับตามคำสั่งนี้ |

## 4. `RobotState` (ตัวแปล → logger/UI)
| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `contract` | str | `"robot_state/0.1"` |
| `t_ms`, `seq`, `robot_id` | | เหมือนข้างบน |
| `joints_commanded_rad` | {ชื่อ: float} | มุมที่สั่งไปจริงหลังผ่านด่านตรวจ |
| `joints_measured_rad` | {ชื่อ: float} หรือ `null` | มุมที่วัดได้ (ซิม หรือเซอร์โวที่อ่านค่ากลับได้) |
| `ee_measured_position_m` | [float×3] หรือ `null` | ตำแหน่งปลายก้ามที่วัดจากภายนอก เช่น ArUco |
| `state_source` | str | `"sim"` · `"servo_readback"` · `"commanded_only"` |
| `stopped_reason` | str หรือ `null` | เช่น `"stale"`, `"disabled"`, `"limit"`, `"estop"` |

**ห้ามบันทึกมุมที่สั่งไปว่าเป็นมุมที่วัดได้** เซอร์โว PWM ไม่ส่งมุมกลับ ให้ใช้ `state_source: "commanded_only"` และ `joints_measured_rad: null`

## 5. กติกาตรวจค่า (ทุกผู้รับ)
1. ทุกตัวเลขต้องเป็น finite (ไม่มี NaN หรือ inf)
2. `grip` อยู่ใน 0–1 และ quaternion มีความยาว 1 ± 1e-3
3. `contract` major version ต้องตรง, `robot_id` และ `profile_version` ต้องตรงกับที่โหลด
4. ชื่อข้อต่อต้องครบและตรงกับโปรไฟล์
5. `seq` ต้องเพิ่มขึ้น ถ้าเท่าหรือน้อยกว่าเดิมให้ทิ้งข้อความ
6. ข้อความผิดกติกา → ไม่ส่งต่อ, บันทึกเหตุผล, และถือว่าเป็นคำสั่งพัก

## 6. กติกาความปลอดภัยที่ผูกกับสัญญา
- `enabled: false`, `mode: "hold"`, `ik_ok: false` หรือคำสั่งเก่ากว่า `max_age_ms` → แขนหยุดที่ท่าปัจจุบัน ไม่ตัดไฟ เพราะแขนหรือของที่ถืออาจตก
- เลน A ต้องส่ง `mode: "hold"` ทันทีเมื่อมือหาย **รวมถึงตอนอยู่ในโซน rate ของ bubble**
- ตัวแปลแขนจริง (C) ตรวจซ้ำเป็นด่านสุดท้าย: ช่วงพัลส์, ความเร็วสูงสุดต่อข้อต่อ, และปุ่มหยุดฉุกเฉิน ต่อให้ชั้นบนผ่านมาแล้วก็ตรวจซ้ำ

## 7. ไฟล์ replay
- บรรทัดแรกเป็น header: `{"contract":"replay_header/0.1","created":"<ISO-8601>","kind":"ee_target","camera":{"width":1280,"height":720,"f_px":null},"notes":""}`
- บรรทัดถัดไปเป็นข้อความชนิดเดียวกันทั้งไฟล์ตาม `kind`
- log กล้องเดิม (`logs/*.frames.jsonl`) ยังใช้ต่อได้ เลน A แปลงเป็น `ee_target` ได้ด้วยสคริปต์

## 8. คำถามที่ต้องปิดในสัปดาห์ 0
- ส่งข้อความระหว่างโปรเซสด้วยอะไร: เรียกฟังก์ชันในโปรเซสเดียวก่อน (ง่ายสุด) หรือ socket/ZeroMQ ตั้งแต่ต้น
- ชื่อแพ็กเกจโค้ดสัญญาและโฟลเดอร์ของแต่ละเลน
- รายชื่อข้อต่อและช่วงมุมของแขนเล็ก (รอ P005) ระหว่างนี้ใช้โปรไฟล์ชั่วคราวจากโมเดลซิม
- `max_age_ms` ค่าเริ่มต้น 200 ms พอไหม (รอผลวัด latency)
- ข้อมูลนิ้วรายนิ้วสำหรับโหมดหลายนิ้ว: เพิ่มเป็นฟิลด์ใน v0.2 ตอน ก.พ.
