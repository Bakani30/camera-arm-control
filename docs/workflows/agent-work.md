# วิธีแบ่งงานและส่งต่อ

## หน้าที่
- ผู้คุมงาน: รักษาเป้าหมาย เลือกขอบเขต เจ้าของ และรวมผล
- ผู้สำรวจ: ตอบคำถามเฉพาะจาก source แบบ read-only
- ผู้ทำงาน: แก้ไฟล์ตาม packet และตรวจผล
- ผู้ตรวจ: ตรวจหลักฐานของงานที่มีผลต่อ control contract, limits, hardware หรือข้อสรุปวิจัย

เป็นบทบาทชั่วคราว ไม่ต้องสร้างทุกบทบาททุกครั้ง และไม่ผูกกับยี่ห้อหรือรุ่นโมเดล AI

## ก่อนแบ่ง
ใช้ docs/templates/task-packet.md ระบุไฟล์จริงและ baseline จาก git status/diff หรือ hash หากไม่มี git แยกเจ้าของไฟล์; shared contracts มีเจ้าของเดียว คนอื่นส่งข้อเสนอ ไม่แก้พร้อมกัน

ตัวอย่างงานขนาน: คน A ตรวจกล้อง/perception, B ตรวจ model/IK/contact, C ออกแบบ logging/metrics โดยตกลง contract ก่อน integration ใช้ fixture ที่ติดป้าย simulated ไม่รายงานเป็นการวัดจริง

## ระหว่างทำ
- Worker ไม่ได้ทำงานคนเดียวใน workspace ห้ามย้อนหรือเขียนทับงานอื่น
- ก่อนแก้ตรวจว่ามีการเปลี่ยนจาก baseline หรือไม่; ถ้ามีให้คืนผู้คุมงานเพื่อรวม ไม่ force overwrite
- ต้องข้าม ownership หรือเปลี่ยน interface ให้คืนผู้คุมงานจัดขอบเขตใหม่
- Child ไม่แตกงานต่อเอง; ใช้หนึ่งชั้นเพื่อลดงานซ้อน
- ส่งเฉพาะบริบทที่จำเป็น ไม่คัดประวัติทั้งแชตถ้าชุดเอกสารสั้นพอ
- ไม่มีเครื่องมือ subagent ให้คนเดียวทำตาม packet ได้; ห้ามอ้างว่ามี independent review หากไม่ได้เกิดขึ้น

## รวมและส่งต่อ
ผู้คุมงานอ่านผลและตรวจจุดเชื่อมที่สำคัญ รับผลตามหลักฐาน ไม่ใช้ชื่อโมเดลเป็นเครื่องรับประกันคุณภาพ งานตรวจอิสระให้ diff/สถานะ/config/คำสั่งจริงพร้อมคำถาม ไม่ให้เพียงคำสรุปของผู้ทำ

จบด้วย outcome, changed files, verification, unresolved risks, next step และปรับ current-state เมื่อจำเป็น งานค้างต้องระบุว่ายังไม่ได้รันส่วนใด การแบ่งงานไม่เพิ่มสิทธิ์ซื้ออุปกรณ์หรือขยับฮาร์ดแวร์
