# M0: Relative mapping จากมือไปจุดเป้าบน mock arm

วันที่ 2026-11-01 · เลน A · ก้าวแรกของ P006 · ร่างรอผู้ใช้อนุมัติ · ยังไม่ commit

## เจตนา
เปลี่ยนตำแหน่งมือหน่วยเมตรจาก `MetricHand` เป็น `EndEffectorTarget` แบบ relative/clutch แล้วเห็นจุดเป้าขยับสดบน mock arm

M0 คือ "relative ล้วน (ฟองเต็มกรอบ)" ใน roadmap ข้อ 7 และ D18 เป็นทั้งตัวเทียบของ hybrid bubble และโครงที่ P006 จะต่อยอด

ผลรอบนี้ใช้ยืนยันว่า M0 ทำงาน แต่ใช้เทียบกับ bubble ไม่ได้ เพราะ roadmap ข้อ 7 ต้องใช้ filter เดียวกันทุกวิธี filter ใน mapper จึงต้องเปลี่ยนได้ และต้องวัด M0 ใหม่หลังมี One Euro

เหตุผล: งานจริงส่วนใหญ่ใช้แนวนี้ ไม่ต้องรู้ depth สัมบูรณ์ และให้ทีมลองการคุมด้วยมือได้โดยไม่รอ IK หรือแขนจริง ดู [survey เดิม](../../research/hardware-notes/2026-10-29-camera-teleop-arm-survey.md)

## เป้าหมาย
- ผู้ใช้กด C แล้วขยับมือ จุดเป้าบน mock arm ตามสดบน Mac หรือ Windows
- ทุกรอบบันทึก `ee_target` เป็นไฟล์ replay ที่เลน B และ C นำไปใช้ต่อได้
- ทำซ้ำได้: เฟรมชุดเดิมให้เป้าหมายชุดเดิม

## ไม่ทำใน M0
- bubble, โซน rate, โหมดละเอียด (`fine`), One Euro: อยู่ใน P006 ส่วนถัดไป
- IK, MuJoCo, การสั่งแขนจริง
- การแก้ภาษากลาง v0.1 และการอ่าน `RobotState` กลับเข้าเลน A
- การหมุน: `orientation_wxyz` เป็น `null` เสมอ
- ท่ามือใหม่: ชุดท่าไปล็อกใน P008
- การลบ `arm_contracts/from_camera_log.py`

## สิ่งที่ถือว่าล้มเหลว แม้เทสต์ผ่าน
- จุดกระโดดตอนมือกลับเข้ากรอบ หรือหลังกด C
- ส่งสัญญาณ `track` ขณะไม่มีมือ มีเฟรมเก่า หรือมีเฟรมกระโดด
- ผลจาก replay หรือข้อมูลจำลองถูกรายงานว่าเป็นผลกล้องจริง

## การตัดสินใจ

- ผลแรกที่เห็น: จุดเป้าบน mock arm แบบสด

## พฤติกรรม

### สถานะ
| สถานะ | เงื่อนไข | ข้อความที่ส่ง |
|---|---|---|
| ยังไม่เริ่ม | ยังไม่กด C หรือ R หรือกด Space | `enabled=false`, `mode=hold`, ตำแหน่งล่าสุด |
| พัก | เริ่มแล้ว แต่ไม่มีมือ, เฟรมเก่า, ค่าเมตรใช้ไม่ได้ หรือเฟรมกระโดด | `enabled=true`, `mode=hold`, ตำแหน่งล่าสุด |
| ตาม | เริ่มแล้ว และเฟรม valid | `enabled=true`, `mode=track`, ตำแหน่งใหม่ |

ทุกเฟรมส่ง 1 ข้อความ และต้องเปลี่ยนเป็น `hold` ในเฟรมเดียวกับที่พบปัญหา

### ขั้นตอนต่อเฟรม
1. รับ `position_m`, `z_m`, `active` จาก `MetricHand` พร้อมเวลา `now` และสถานะ armed จาก `HandControl`
2. เฟรมแรกหลังพัก หรือเฟรมที่ห่างจากเฟรมก่อนเกิน 500 ms: จับ reference ใหม่ รีเซ็ต filter จุดไม่ขยับ mapper ตรวจช่วงเวลาเอง เพราะ `MetricHand.active` ยังเป็น `True` หลัง gap
3. เฟรมถัดไป: ตรวจเฟรมกระโดด แล้วกรองด้วย EMA
4. คูณ gain และแปลงแกนจากระยะที่กรองแล้วของเฟรมนี้ แกนลึกใช้ deadband แบบ backlash กับค่าตำแหน่งที่กรองแล้ว: ค่าที่ค้างขยับเมื่อห่างจากตำแหน่งเกิน 15 มม. แล้วใช้ผลต่างของค่าที่ค้าง ห้ามใช้ deadband กับระยะต่อเฟรม เพราะแกนลึกจะไม่ขยับเลย
5. บวกเข้า `desired` แล้ว clamp ในกล่อง จึงไม่สะสมระยะเกินขอบ
6. เลื่อน `emitted` ไปหา `desired` ไม่เกินเพดานความเร็ว
7. สร้าง `EndEffectorTarget` จาก `emitted`

ตอนเข้าสถานะพักหรือยังไม่เริ่ม: `desired` เท่ากับ `emitted` ทันที ระยะที่ยังตามไม่ทันถูกทิ้ง มือกลับมาแล้วนิ่งอยู่ จุดจึงต้องนิ่ง

ปุ่ม R เริ่มตามเหมือน C ตามพฤติกรรมเดิมของ `HandControl.reset()` และตั้ง `desired` เป็นจุดเริ่ม ระหว่าง `hold` ตำแหน่งที่ส่งยังค้างอยู่ `emitted` เริ่มเลื่อนกลับตามเพดานความเร็วเมื่อเข้าสถานะตาม ห้ามกระโดด

`grip` ใช้ `GRIP_BY_CODE` เดิม: ฝ่ามือเปิด = 0, กำมือ = 1, ค่าอื่นคงค่าเดิม โดยอยู่ใต้กติกาการค้างก้ามด้านบน

## โครงสร้าง
- **ใหม่ `camera_gestures/mapping.py`:** `MappingConfig` และ `RelativeMapper` เป็น logic ล้วน ไม่ import cv2, MediaPipe หรือ arm_contracts คืนตำแหน่ง สถานะ และ `grip` โดยนิยาม code→grip ในไฟล์นี้เอง ไม่ import จาก `from_camera_log` ซึ่งเป็นไฟล์ชั่วคราว
- **`camera_gestures/app.py`:** เพิ่ม `--mapping relative` ต้องใช้คู่ `--calibration` และ `--palm-length-m` สร้างข้อความ, ส่งเข้า `MockArm`, เปิดหน้าต่าง mock และเขียน `logs/<stem>.ee_target.jsonl` ทีละบรรทัดให้เหมือน frame log เพราะ `write_replay` เขียนตอนจบรอบเท่านั้นและงานหายถ้าโปรแกรมล่ม ไฟล์ต้องอ่านด้วย `read_replay` ได้; ถ้าไม่ใส่ flag ทำงานเหมือนเดิม
- **`arm_contracts/mock_arm.py`:** `render` รับกล่องและจุดเป้าสำหรับวาดเป็นตัวเลือก ค่าเดิมไม่เปลี่ยนภาพ นี่เป็นเครื่องมือ ไม่ใช่สัญญา
- **ไม่แก้ `metric.py`, `control.py`:** mapper อ่านค่าจากภายนอก และคิดผลต่าง Z เอง
- Frame log เพิ่มฟิลด์ mapper พอให้ replay คำนวณซ้ำได้

## การทดสอบ

### อัตโนมัติ (`tests/test_mapping.py`)
- แกนและเครื่องหมายครบ 3 แกน และ gain ตรงสูตร
- มือหายแล้วกลับมาที่ตำแหน่งอื่น: จุดไม่เปลี่ยนในเฟรมนั้น
- Clamp ทุกแกน ไม่สะสมระยะเกินเมื่อถอยกลับ
- เพดานความเร็วกับ dt ต่าง ๆ รวมทั้งหลังกด R
- เฟรมกระโดด, เฟรมเก่า และ NaN ได้ `hold` ทันที
- Deadband แกนลึกไม่ทำให้ค่ากระโดด และการดันมือช้า ๆ ทีละน้อยยังขยับจุดได้
- Gap เกิน 500 ms ที่ `active` ยังเป็น `True`: จุดไม่ขยับ แม้ `z_m` เปลี่ยน
- ไฟล์ `ee_target` ที่ถูกตัดจบกลางคันยังอ่านด้วย `read_replay` ได้ถึงบรรทัดเต็มสุดท้าย
- ทุกข้อความผ่าน `Receiver` ของสัญญา
- เฟรมชุดเดิมให้เป้าหมายเดิมทุกตัว
- ตามไม่ทันแล้วมือหาย: กลับมาแล้วมือนิ่ง จุดไม่ขยับต่อ
- กด R ระหว่างพัก: ตำแหน่งที่ส่งไม่เปลี่ยนจนกลับมาตาม แล้วเลื่อนตามเพดานความเร็ว
- ก้ามไม่เปลี่ยนระหว่างพัก และไม่เปลี่ยนในเฟรมแรกที่กลับมาตาม
- กล่องอยู่ในขีดรัศมีของ `small_arm_v1` และเลือกจุดเป้าทดสอบที่ soft limits ยอมรับได้
- ชุดเทสต์ทั้งหมดผ่านใน venv ที่มี `cv2` และ `numpy`

## ข้อจำกัดและความเสี่ยง
- **กำมือทำจุดขยับได้:** การกำมือเปลี่ยนความยาว landmark 0–9 และ `z_m` แต่ยังไม่มีตัวเลข
- **สเกลขึ้นกับขนาดฝ่ามือ:** ฝ่ามือ 11 ซม. ยังเป็นค่าประมาณ และไม่ผ่านเกณฑ์สเกลอาจมาจากค่านี้ ให้บันทึกแยกจากบั๊ก mapping คนปิดลูปด้วยตาได้ เกณฑ์จึงเผื่อ 25% ส่วน f ยังมีผลกับ `z_m` และแกนลึก เกณฑ์แกนลึกจึงเผื่อ 50%
- **Noise ของ Z เข้า X/Y:** ตามที่ P002 บันทึกไว้ เมื่อมืออยู่ห่างกลางภาพ
- **กล่องตรวจแค่ reach:** สุ่ม 60,028 ท่าที่ผ่าน soft limits ครอบคลุม 671/768 ช่องขนาด 2 ซม. ช่องที่เหลือยังแยกไม่ได้ว่าเพราะสุ่มไม่พอหรือไปไม่ถึง ไม่ได้ตรวจท่าก้มตรงลง ซึ่งเลน B ต้องตรวจเมื่อทำ IK
- **ก่อนต่อแขนจริง:** จุดเริ่มคงที่ใช้ไม่ได้ถ้าแขนไม่ได้อยู่ที่จุดนั้น ต้องตัดสินวิธีรับตำแหน่งแขนและแก้สัญญาก่อน การผ่าน M0 ไม่อนุญาตให้ขยับแขนจริง
