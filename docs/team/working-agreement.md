# วิธีทำงานร่วมกัน (แบบเลน + จับคู่หมุนเวียน)
รุ่น 2026-10-22

แต่ละคนเป็นเจ้าของหนึ่งเลน เพื่อให้ทำงานพร้อมกันได้ และจับคู่ข้ามเลนหมุนเวียน เพื่อให้ทุกคนเข้าใจทั้งระบบ ปัญหาระหว่างเลนจะเจอทุกวันศุกร์ตอนยังเล็ก แทนที่จะไปเจอทีเดียวตอนรวมใหญ่ปลายเดือน

## จังหวะหนึ่งสัปดาห์
| วัน | ทำอะไร |
|---|---|
| จันทร์ | วางแผน 30 นาที (C นำ): แต่ละคนบอกว่าศุกร์นี้เลนตัวเองจะส่งอะไร และต้องการอะไรจากเลนอื่น · คุยเรื่องเปลี่ยนภาษากลาง (ถ้ามี) |
| อังคาร–พฤหัส | ทำงานในเลน · หนึ่งวันจับคู่กับคนจากเลนอื่น (เขียนคู่หรือตรวจงาน) |
| ศุกร์ | รวมงานครึ่งวัน: ต่อทุกเลนจริง, รันเทสต์ + replay, เดโมสั้นๆ ผู้รวมงานจดว่าอะไรต่อกันไม่ติด |

## บทบาท
- **เจ้าของเลน:** ตัดสินใจเรื่องในเลนได้เอง และรับผิดชอบให้งานรวมได้วันศุกร์
- **ตัวสำรองเลน:** วงกลม A → B → C → A เป็นคนตรวจ PR ของเลนนั้นเป็นหลัก และรับต่อถ้าเจ้าของเลนไม่อยู่
- **ผู้รวมงานประจำสัปดาห์:** หมุนกันถือทั้งสามคน คุมการรวมงานวันศุกร์
- **คู่ข้ามเลน:** หมุนทุก 2 สัปดาห์ A–B → A–C → B–C

## กติกา
1. **ภาษากลางมีเลขเวอร์ชัน:** ใครก็เสนอแก้ได้ แต่เปลี่ยนจริงเฉพาะวันจันทร์ และ C เป็นคนอนุมัติ
2. **เสร็จ = รวมได้:** งานที่รันได้แค่บนเครื่องตัวเองยังไม่นับว่าเสร็จ
3. **ว่างแล้วไปช่วย:** ช่วงรอของหรือรอผล ให้ไปช่วยเลนที่ช้าที่สุด
4. **ตรวจข้ามเลน:** PR ทุกอันต้องมีคนจากเลนอื่นตรวจ
5. **ใช้ AI ช่วยเขียนโค้ดได้:** แต่เจ้าของต้องอธิบายโค้ดได้ตอนรวมงาน
6. **ติดเกิน 1 วัน:** บอกในแชตทีมเลย ไม่ต้องรอวันศุกร์
7. **แขนจริงต้องมีคนคุมหน้างาน:** ปุ่มหยุดอยู่ในมือ และพื้นที่ปลอดคน การผ่านในซิมไม่ได้อนุญาตให้ขยับแขนจริงเอง

## Git และ PR
- `main` ต้องรันเทสต์ผ่านเสมอ (`python -m unittest discover -s tests -v`) และ CI บน Windows ต้องเขียว
- หนึ่ง branch ต่องานหนึ่งชิ้น ตั้งชื่อ `<โรล>/<เรื่อง>` เช่น `a/metric-mapping`, `b/mujoco-setup`, `c/contracts-v0.1`
- หนึ่ง PR หนึ่งเรื่อง: งานไม่เกี่ยวกันแยก PR
- อัปเดตงานด้วย `git pull --ff-only` ก่อนเริ่มทุกวัน
- งานทุกชิ้นมี issue บน GitHub ระบุโรลด้วย label `lane:A` / `lane:B` / `lane:C` / `team` และเขียนว่า "เสร็จแปลว่าอะไร"
