# P001 — ความเป็นไปได้ของต้นแบบแรก
สถานะ: ready (sprint 1, 2–13 พ.ย.) · โรล B (ดู docs/team/roster.md) · ยังไม่มีผลรัน

> อัปเดต 2026-10-22: ทุกคนมีเครื่อง Windows ที่รันซิมและมีกล้อง ไม่ต้องแย่ง ASUS เครื่องเดียว ใช้คำสั่งสคริปต์จาก P003 เป็นอินพุต ไม่ต้องรอ mapping ของ A ผลลัพธ์ต้องส่งคำสั่งข้อต่อตามภาษากลาง 2 ใน docs/interfaces/contracts-v0.1.md

## เป้าหมาย
ระบุชุดกล้อง→ข้อมูลมือ→baseline→ซิมหนึ่งแขนที่ทดลองได้บน ASUS Windows พร้อมข้อจำกัดและหลักฐานเลือกเครื่องมือ

## ขอบเขต
- ตรวจ OS, GPU/driver, Python/runtime ที่มีอยู่ และข้อจำกัดติดตั้ง
- ประเมินซิมหนึ่งตัวและโมเดลหนึ่งชุดก่อน; ยืนยัน joint names, limits, end-effector และ contact
- ระบุทางรับภาพและติดตามมือ; แยก estimated depth จาก metric depth
- จัดทำ protocol สั้นสำหรับขยับปลายแขน บันทึก timestamp และหยุดเมื่อ tracking หาย
- บันทึกผลจริงเท่าที่มีสิทธิ์เข้าถึง; ถ้าไม่มี ASUS ให้ส่งแผนและ checklist โดยระบุผลซิมบน ASUS เป็น NOT RUN

## เครื่องพัฒนาและเครื่องทดสอบ — ยืนยัน 2026-10-02
- พัฒนาและเตรียมโค้ด/config/คู่มือบน MacBook Air M1 RAM 8 GB หรือ ASUS; ตามแผนของผู้ใช้ ไม่รันซิมบน M1
- ASUS ใช้ได้ทั้งพัฒนา กล้อง เตรียมข้อมูล ฝึก ML ซิม และเชื่อมฮาร์ดแวร์ ไม่จำกัดเป็นเครื่องซิมอย่างเดียว; งานฝึกโมเดลและเชื่อมฮาร์ดแวร์ยังอยู่นอกขอบเขต P001
- รันซิมและตรวจ Windows compatibility บน ASUS; ตรวจสเปกและ dependencies ก่อนล็อกเวอร์ชัน การกำหนดบทบาทเครื่องยังไม่ใช่ผลทดสอบซอฟต์แวร์
- ส่งโค้ดและไฟล์ทดสอบให้ ASUS รันใน environment ของเครื่องนั้น ไม่คัดลอก venv จาก Mac
- ไม่ต้องรอเครื่องแล็บ RTX 4090 และไม่เพิ่ม streaming หรือ distributed runtime ในต้นแบบนี้
- ยังไม่มีผลรันซิมบน ASUS; การแบ่งเครื่องไม่ถือว่า P001 ผ่าน

## เจ้าของ/ไฟล์
ผู้คุมงานมอบหมายก่อน dispatch; output ที่เสนอ: docs/feasibility.md
อย่าแบ่งหลาย worker เขียนไฟล์นี้พร้อมกัน ให้คนสำรวจส่งผลกลับผู้รวมเอกสาร

## เกณฑ์จบ
มีตัวเลือกพร้อมแหล่งอ้างอิง/เวอร์ชัน เหตุผล ความเสี่ยง คำสั่งที่รันและผล หรือข้อจำกัดที่ทำให้ยังรันไม่ได้ พร้อมคำถามที่จะปิดก่อน P002 การตรวจเอกสารอย่างเดียวไม่ถือว่า Windows compatibility ผ่าน

## ไม่รวม
ซื้ออุปกรณ์ ฝึกโมเดลใหม่ สองมือ และการเลือกทุกโมเดลพร้อมกัน
